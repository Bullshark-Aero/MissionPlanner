BSMP title identity implementation plan

Status: approved for implementation · Version: v1.1.0 · Created: 2026-09-07 13:24 Europe/London

Predecessor: bsmp-title-identity-plan--202609071320--v1.0.0--version-and-controller-title.html. This revision removes the proposed firmware-hash catalog and defines a telemetry-owned BSA semantic-version contract.

Outcome

Show an unambiguous BSMP, BSA firmware, upstream ArduPlane, flight-controller model, and controller UID identity in the application title. BSMP must only show a BSA firmware version supplied by the connected autopilot.

Telemetry contract

A future BSA ArduPilot build will append BSA V<semver> to its normal firmware banner, for example ArduPlane V4.7.0 (commit) BSA V1.5.0. This remains within a MAVLink STATUSTEXT payload, is readable by ordinary ground stations, and is returned by the existing banner request. ArduPlane remains the authority for the upstream version; BSA firmware remains the authority for its semantic version.

Implementation

  1. Format the base BSMP title from the application product name and product version.
  2. Parse only the explicit BSA V<semver> banner marker. Do not infer a BSA version from a commit hash.
  3. When the marker is present, display BullShark Mission Planner <version> ArduPlane V<BSA version> Based on V<upstream version> <controller> <UID>.
  4. When the marker is absent, show the ordinary reported firmware identity, controller, and UID without claiming a BSA version.
  5. Prefer the canonical MAVLink UID2 value; normalize the legacy serial-banner UID only as a fallback.
  6. Reset the title to the BSMP identity on disconnect.
  7. Add focused tests for BSA and ordinary banners, prerelease semantic versions, invalid markers, canonical/fallback UID handling, missing fields, and disconnected state.
  8. Add a durable Judicar firmware todo requiring the next BSA firmware release to emit and test the banner marker.

Verification and delivery

  1. Run focused tests and a Release build on the supported Windows build environment.
  2. Inspect representative generated titles, including the current firmware fallback and a future BSA banner.
  3. Commit on platform/mission-planner/identity-title, push that task branch, and open a pull request to the default branch.

Rollback

Revert the feature commit. No aircraft parameters, firmware, hardware, or persisted aircraft configuration are changed.
